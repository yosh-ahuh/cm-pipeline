# ブランドメモリ（Brand Memory）設計

「**1組織＝1ブランド。その組織で生成した動画をAIがラーニングし、1ブランドに特化していく**」（ユーザー定義 2026-09-22）を実現する機能設計。
現状は**静的ブランドキット**（ロゴ/カラー/発音辞書）を各生成に適用するのみで、過去コンテンツからの学習・特化は無い（[[workspace-brand-model]]）。本設計はその「学習/特化レイヤー」を段階導入する。

## 基本方針
- **重い学習（FT）を最初からやらない**。まず「**過去の蓄積を参照して次の生成に効かせる**」参照ベースで、体感の"特化"を出す。
- データ基盤は既にある：`projects.spec.selections`（媒体/業種/ターゲット/伝え方/トーン）、`generations`/`renders`（org_id単位で蓄積）、`brands.assets`（キット）。
- ワークスペース＝ブランド＝1組織なので、**org_id 単位で集計**すれば「そのブランドの傾向」になる。

## フェーズ

### Phase 1 — ブランド既定値（アプリ側・worker不要）★最初に実装
そのブランドの過去 `projects.spec.selections` を集計し、**ウィザードの初期選択をそのブランドの"いつもの設定"に**する。「選ぶだけ」がブランドを重ねるほど速くなる＝体感の学習。
- `window.__brandDefaults()`：現org の projects を新しい順にN件取得→各軸（media/industry/target/angle/tone）で最頻値を算出。
- 新規CM開始時（gotoWizard）に `sel` と選択カードへ反映。demo既定はブランド履歴が無い時のフォールバック。
- ウィザードに控えめな注記「このブランドのいつもの設定を反映しました（変更できます）」。
- ワークスペースのプロフィールに「このブランドの傾向」サマリ（よく使う媒体/トーン/本数）。

### Phase 2 — 生成への参照注入（worker側・--live必要）
- **ビジュアル参照**：`brands.assets` ＋ 過去の"採用"レンダーの静止画を、画像/動画モデルに**スタイル/参照画像**として渡す（fal の reference/style 対応）。
- **コピー参照**：過去の効いた台本・ナレーションを**few-shot**として台本生成に与え、ブランドの声に寄せる。
- **発音/表記**：既存の発音辞書に加え、ブランド固有の言い回し・NG表現を蓄積し適用。
- 実装：`worker.py`/`cm-pipeline` が生成前に org の参照コーパスを取得→各ステージのプロンプト/参照に注入。

### Phase 3 — 学習ブランド（重い・将来）
- per-brand の embeddings インデックス（RAG）／必要なら軽量FT。ブランドのコーパス（台本・レンダー・採用/不採用フラグ）を教師に。
- 「採用/不採用」の明示フィードバック導線が前提（Phase 2で種を蒔く）。

## データ／スキーマ
- Phase 1 は**スキーマ変更不要**（既存 projects.spec を集計）。
- Phase 2/3 で必要になりうる追加：`renders.approved`(採用フラグ)、`brand_memory`(集計キャッシュ)、参照用の署名URL経路。→ 着手時に定義。

## 進捗
- ✅ **Phase 1 実装済**：`window.__brandDefaults()`（現org の projects.spec.selections を最大30件集計→各軸の最頻値・媒体は4割以上）。`applyBrandDefaults()`＋`applySelToUI()` を `gotoWizard` で呼び、ウィザードの初期選択をブランドの“いつもの設定”に。注記「このブランドのいつもの設定を反映しました」。履歴2本未満/未サインインは demo 既定のまま。スキーマ変更なし。stub履歴で動作確認済み。
- ⏳ Phase 2/3 未着手（worker側の参照注入／学習）。
