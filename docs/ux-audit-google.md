## 1. 主要UX原則（要約）
- **リサーチ起点**：思い出す→定義→発想→試作→検証の反復。仮定でなく検証で設計。エッジケース（うまくいかない時）も設計する。（C1M3 / C2M2）
- **ユーザーストーリー**：「[誰]として、[何]したい、[なぜ]」。設計の要件チェックリストになる。（C2M2）
- **KPI**：所要時間・離脱率・エラー率・ナビ vs 検索の利用・SUS。（C4M1）
- **情報設計（IA）**：階層/マトリクス/逐次/DB。サイトマップ・ランドマーク・F字スキャン。**ゲシュタルト**（類似=同機能／近接=関連／共通領域=枠で囲ってグループ化）。（C3M2 / C6M1）
- **アクセシビリティ**：恒久/一時/状況的な制約に対応（curb-cut効果）。色だけに頼らない／高コントラスト／可変文字サイズ／代替テキスト／字幕・書き起こし／キーボード操作／一貫ナビ／馴染みあるアイコン＋ラベル／シンプルに。（C1M2 / C2M2 / C4M1）
- **インタラクション**：トリガ＋アクション＋モーション。成功の明示。前後移動・出発点に戻れる。モーション速度はa11yに合わせ、音/動きは任意でミュート可。（C5M4）
- **ビジュアル**：タイポ階層・強調・余白・整列グリッド・コンテインメント（枠/塗り/影）・アイコン体系・**デザインシステム（再利用部品で一貫性）**。（C5M1–3）
- **コンテンツ**：平易な言葉・専門語排除・ペルソナ向けに書く。低リテラシー層はパターン/アイコン/ジェスチャを知らない前提で明示。（C1M2 / C2M2）

## 2. Spot向け改善提案（優先度）
### P0（最重要・低ITリテラシー直結）
1. **初回オンボーディング＋ホーム常設「3ステップ」** — 未知機能の解決策。主アクション「新規CM」を明確に。（C5M2）
2. **作成フローの逐次モデル可視化：進捗＋可逆** — ステップ「N/4」表示、常時「戻る」＋「保存して後で続ける」。行き止まりを作らない。（C6M1 / C5M4）
3. **成功＋システム状況フィードバック（遅いAIジョブ）** — 進捗/ETA/キュー位置、明確な「完成しました」＋次アクション。スピナー放置禁止。（C5M4）
4. **クレジット消費前の平易な確認** — 「この生成で◯クレジット使います。残り◯。よろしいですか？」（C1M4 / C2M2）
5. **空状態・エラー状態を平易に設計（エッジケース）** — 空メディア/空コレクション/残高0/生成失敗、非技術者向けの日本語（エラーコード無し）。（C2M2）

### P1（発見性・信頼・理解）
6. **メディア：検索＋フィルタ＋状態バッジ、ゲシュタルト活用** ✅ 検索/件数は実装済。状態チップ（下書き/生成中/完成/書き出し済）を追加余地。（C3M2 / C6M1）
7. **コレクション：カードから1タップで「追加/移動」**。（C3M2）
8. **タイポ階層の総点検** — 各画面 H1＋サブ＋本文で主アクションに目が行く。（C5M1–2）
9. **台本/絵コンテ：各選択にプレビュー＋「これは何？」ヘルパー**、専門語回避。（C1M2 / C5M4）
10. **ダークのデザインシステム化＋a11y** ✅ トークン済。**状態は色＋アイコン＋テキスト**（色だけ禁止）。（C5M3 / C1M2）
11. **チーム/請求：席・クレジット上限を平易＋次にどうなるか**。席/brandsは現状“表示のみ”＝実効しない上限を匂わせない（正直さ）。（C1M4）

## 3. アクセシビリティ・チェックリスト（Spotで未対応の可能性）
**知覚可能**
- [ ] 状態/エラーを**色だけで伝えない**（アイコン＋テキスト併記）
- [ ] ダーク背景の**コントラスト比検証**（✅ 一度実施・faintは装飾専用）
- [ ] 意味ある画像/サムネに**代替テキスト**、装飾は非読み上げ
- [ ] チュートリアル/プレビュー動画に**字幕・書き起こし**
- [ ] **可変/ズーム対応の文字**（OSフォント拡大・ブラウザズームで崩れない）

**操作可能**
- [ ] 作成フロー全体の**キーボード操作**＋ダークで見えるフォーカス
- [ ] **一貫したナビ**配置とラベル
- [ ] 破壊的/クレジット消費操作に**確認**（誤タップ防止）
- [ ] `prefers-reduced-motion` 尊重（✅ 実装済）、音/動きは任意
- [ ] ウィザードに前後＋出発点に戻る（行き止まり無し）

**理解可能**
- [ ] 平易な日本語・専門語なし、各選択/設定にヘルパー
- [ ] 馴染みあるアイコン＋**必ずテキストラベル**
- [ ] 神経多様性配慮でシンプル・一貫（1画面1主アクション）＋空/エラーにも適用
- [ ] 非技術的なエラーメッセージ＋復帰の次手

**堅牢/支援技術**
- [ ] **スクリーンリーダー**検証（button/divの役割・アクセシブル名）
- [ ] 状態変化（生成完了/失敗）を**ARIA live**で通知
- [ ] スイッチ/キーボードのみで使える（フォーカス順＝視覚順）

## 3.5 追補（残りPDF精読で得た新原則・2026-09-21）

**レイアウト/レスポンシブ（C6M2/C7M1）**
- above-the-fold（≈800px）に主情報＋主CTAを置く。desktop基準 1440×1024。
- ナビ4類型：バー／タブバー（現在地表示）／隠しメニュー（ハンバーガー）／ハブ。Spotの浅い階層は**常時可視のバー/ハブ**が最適＝低ITでは隠さない。
- 狭幅では sidebar→アイコン列/ハンバーガー＋フライアウトへ折り畳む計画を先に持つ。
- **60-30-10**：60%中間色/30%補色/10%アクセント。アクセントは**主CTA専用**（1画面1アクセント）。

**コンテインメント（C7M1）**：divider/border/fill/shadow＋余白でグループ化。密な画面（ワークスペース/絵コンテ/書き出し）に適用。

**計測（C7M1）**：作成ファネルに KPI を計装＝**ステップ別離脱率・所要時間・エラー率・完了率（開始→書き出し）**。P0の定義＝「機能する・公平/アクセシブル・**誤認させない**」。課金/クレジット面で**コストを誤認させ得るものは全てP0**。

**リスト順（C2M3 系列位置効果）**：推奨/重要な選択肢は**先頭か末尾**に（中央に埋めない）。ウィザードの選択肢・ホーム・メディアに適用。

**a11y追補（C6M2）**
- DOMの**見出し階層 H1/H2/H3**（視覚サイズだけでなくタグ）＝SRのページ内ナビ。各画面に論理的H1を1つ。
- 対話要素に**アクセシブル名＋role＋状態**（展開/選択/チェックの読み上げ）、関連コントロールは group 化（「1/8」）。
- **ズーム/文字拡大でのリフロー**（重なり・切れ無し）。低ITはOSズーム依存が多い。
- アイコンは**alt＋文化的に中立**（必ずテキストラベル併記）。

## 4. 通底する結論
Spotの既存の勘（1画面1主アクション・平易な言葉・ヘルパー・トークン）は正しい。教材が示す最大の伸びしろは：**ウィザードの進捗/可逆・遅いAIジョブの成功&状況フィードバック・クレジット消費前の平易な確認・空/エラーのエッジケース設計・ダークのa11y（コントラスト/色だけ禁止/キーボード・SR対応）**。
