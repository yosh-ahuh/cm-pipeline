# Spot — 整合性・未詰め・未決定 監査（2026-09-22）

アプリ全体（`spot-app/index.html` ＋ migrations ＋ worker ＋ docs）を横断調査し、**①実装と設計/UIの矛盾、②詰めきれていない箇所、③まだ決まっていない意思決定**を洗い出して整理したもの。行番号は特記なき限り `spot-app/index.html`。

> 目的は「隠れている前提」を可視化すること。多くは *正直にトースト表示* されており詐称ではないが、**有料ユーザーが誤解しうる箇所**を最優先で列挙する。

---

## 0. 最重要リスク（TOP5）

1. **「CMができあがりました／書き出し完了・9本」なのに実ファイルが無い場合がある。** 生成が本物になるのは worker.py が `--live`（fal キー）で常駐しているときだけ。既定はドライラン（ジョブを done にするが素材を作らない）。この状態でも UI は完成を宣言し、9本の“動画风”タイルを見せ、ダウンロード/ZIP/共有は偽トースト。しかも**クレジットは消費済み**（6228行）。→ 誠実さの最大リスク。
2. **自動チャージ・完了メール設定は「見た目だけ」。** DB/localStorage に保存されるが、実行するバックエンドが存在しない（worker/webhook に通知・課金コード無し）。お金と期待に触れるため信頼リスク大。
3. **コンプラ/QCバッジが常時ハードコードで「検証済み」表示。**「実在人物との類似チェック済み」「発音辞書1件適用」「C2PA記録（実際はテスト証明書）」を毎回“完了”として提示。マーケが依拠するAI安全性の主張が未実装。
4. **課金導線が本番 config.js で丸ごと不活性。** `stripeLinks` 未定義のため、アップグレード・全クレジットパック・請求ポータルが「準備中」トーストのみ。正直表示だが、今は誰も購入できない。
5. **有料特典「複数ブランド管理」が未提供。**（¥59,800の Team 以上で販売、brands UI は単一のみ）。現状 `soon:true` の「近日」タグで正直に緩和済み＝タグを外す前に実装必須。

## C. デザインシステム整合（実装で直せる）

### C-1. 未定義CSS変数（High）
- **`--bad` が未定義**（1328 `.member-row .rm:hover { color: var(--bad, #c4553d) }`）。インラインfallbackで描画されるが `--crit`(#E07A64) と不一致のオフブランド色。→ `var(--crit)` に置換。**コード上の未定義変数はこれ1件**（`--card` は撤去済み。`--glow/--glow-shadow` は今回追加＝定義・使用済み。`--scrim` は定義済み・未使用＝ボトムシート実装待ちのWIP）。

### C-2. 角丸トークンの拡大に追随していない“ドリフト”（Med）
角丸トークンを拡大（`--r-sm 8→10 / --r-md 12→14 / --r-lg 16→20 / --r-xl 24→28`）した際、多くのリテラルが**旧値のまま**残存。design-system.md §10-D「非トークン角丸撤廃」は**事実と不一致**。
- `.pack-card` 12px（1227）だけ他カード（`--r-lg` 20px）より角が立って見える。→ `--r-lg` に統一。
- 10/12px 直書き（`.sb-wscard`/`.ws-trigger`/`.voice`/`.move-menu` 等）→ `--r-sm`/`--r-md` へ。2-4px の装飾チップは可。
- 入力の角丸: 通常 `.fld input`=`--r-sm` / 認証 `.auth-form .field input`=`--r-lg`。意図なら文書化、違えば統一。

### C-3. コントラスト（Med・低ITリテラシー層に直結）
design-system.md §7 が「`--faint` は AA 未満・本文禁止」と明記しているのに、**補助/説明テキストに使用**:
- `.field-hint`(486)・`.multi-note`(618)＝ヘルパーテキスト（この層には必須情報）
- `.plan-card .pc-sub`(1225)・`.pack-card .pk-unit`(1239)＝カード上の説明
→ いずれ `--muted`（AA適合）へ。`--faint` はアイコン/プレースホルダ/区切りに限定。

### C-4. トークン外リテラル（Low-Med）
- `.hero-new` グラデの `#1B2352` は `--accent-soft`(#1B2350) のドリフト重複／`#EEF0F8`・`#B4BAD4` はトークン無しの本文色 → `--accent-soft`/`--ink`/`--muted` へ（または hero 専用トークン化）。
- `#FFC933`（415/424）は `--warn`(#E4B14C) と別のゴールド → `--warn` か専用ハイライトトークン。
- `#0F1A14`（340/718/889、緑面上の文字）を3回コピペ → `--on-good`（or `--on-solid`）を定義して参照。
- 単色 `#fff`（`.ro-banner`/`.ws-ic`/`.btn-danger`/`.btn-primary:hover`）→ `--on-accent`。

### C-5. 体系の穴（Low）
- 未使用トークン `--radius-sm`（tokens.css 70）。
- 未使用バッジ変種 `.badge--danger/--warn/--success`（ライブラリとして許容）。`--warn`/`--brand-red` に `-soft` が無い（good/crit/cool/accent にはある）＝トークンの穴。
- `.btn-danger`（1445で使用）が design-system.md のボタン表に無い。

## E. まだ決まっていない意思決定（要ユーザー判断）
「詰めきれていない/決まっていない」の核。各項目 **「本物にする / デモと明示する / 隠す・撤去する」** の三択が必要:

1. **生成の本番稼働** — worker.py `--live` を常駐デプロイするのか？ しないなら「完成/書き出し/DL」を実 renders でゲートし、デモ状態を明示すべき。（TOP1）
2. **共有リンク** — 実装するか、当面隠すか。
3. **一括ZIP DL** — 実装するか、実 renders 時のみ活性か。
4. **自動チャージ／残高通知** — 実行バックエンドを作るか、パネルごと「近日」にして保存無効化するか。（お金絡み）
5. **完了/お知らせメール** — サーバ通知を実装するか、トグルを外すか。
6. **コンプラ/QCバッジ** — 実検証に紐づけるか、静的主張を撤去/条件表示にするか。C2PA は商用CA購入まで「対応」表現を保留するか。
7. **複数ブランド管理** — brands UI を複数対応にするか、「近日」タグを維持するか。
8. **クレジット単価/プラン価格** — ハードコード暫定値を確定するか。
9. **優先サポート** — 運用で差別化する実体があるか。
10. **入力/カードの角丸スコープ** — 認証だけ `--r-lg` を意図とするか、全体統一か。
