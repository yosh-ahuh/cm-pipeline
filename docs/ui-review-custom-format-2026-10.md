# UI 改善案レビュー: 配信先ステップの「カスタム書き出し」案（2026-10-10）

対象: ユーザー提供のモック 2 枚（ステップ 1「どこで流す広告ですか?」に 4 枚目のカード「カスタム」を追加。未選択＝中身を薄く予告、選択＝展開）。
目的: 案の要素を分解し、現行フロー（7 ステップ・上部横一列ステッパー）へ**部品単位**で取り込む判断材料にする。
ロードマップ反映: `docs/design-system.md` §10 P4。

## 1. 案から読み取れる要素

| # | 要素 | モックの表現 |
|---|---|---|
| a | カスタム書き出し | 縦横比: 縦長ポスト 4:5 ／ シネマ 21:9 ／ 比率を手入力（16 : 9）。解像度: フル HD 1080p ／ HD 720p ／ 4K 2160p ／ px を手入力（1920 × 1080） |
| b | 段階開示 | カード未選択時は内側の選択肢をグレーで予告し、選択で有効化（カード全体が青枠＋塗りチェック） |
| c | 選択状態の表現 | 選択＝塗りの青チェック＋青枠、未選択＝輪郭のみ。カード文言は「名前（太字）＋効く型の一言」 |
| d | 主操作の配置 | 「次へ」を下部固定フッターの右端に 1 つ |
| e | 画面骨格 | 左に縦のステップ列（4 ステップ）、上に細い進捗バー ※P1 以前の構成 |

## 2. 全体に取り込む価値があるもの（裏側の変更なし・先に実施）

1. **段階開示カードの部品化**（b）: 「選ぶと中が開く」カードを共通部品にし、次の場所に適用。
   - 伝えたいことステップの業種サブセクション（いまは常時表示）
   - 素材ステップの音楽参考（MP3 / YouTube）
   - 目的・届ける相手の自由入力チップ（「その他」を選んだら入力欄が開く）
2. **選択の結果をその場で見せる**（a の派生）: 配信先・形式の選択で書き出し本数とクレジットが変わることを、カード直下に 1 行で出す。例「この選択で 3 案 × 2 形式 = 6 本」「4K は書き出しに時間がかかります」。現行は右パネルの推奨構成にしか無い。
3. **カード文言の型を統一**（c）: 全ステップのカードを「名前＋効く理由 1 行」に揃える。目的・相手・伝え方は 1〜3 行でばらついている。
4. **主操作の固定フッター**（d）: 画面幅に関係なく右下に主ボタン 1 つ。モバイルではボトムナビと重ならない位置（`bottom: calc(64px + safe-area)`）に。

## 3. そのまま採用すると問題になるもの

| 論点 | 内容 | 対応案 |
|---|---|---|
| カスタム形式の裏側 | 現行は wide / vertical / square の 3 形式に Remotion の構成 ID、Veo の出力比（16:9 / 9:16 のみ）、スチルの切り出し位置（anchor）、配信先ごとの上限（尺・容量）が紐づく。自由比率・自由 px は検証できない組み合わせが無限に出る。4K は生成コストと時間が跳ねる | **4:5 と 21:9 をプリセット**として追加する設計から始める（§4）。自由入力は Pro 以上か後回し |
| 入れ子の選択が重い | 1 枚のカードに 2 群のラジオ＋手入力＝3 階層。対象ユーザー（低 IT リテラシー）には多い | カスタムは**ボトムシート**で 1 群ずつ聞く。カードには選択結果の要約だけ表示 |
| 選択の意味が混在 | 外側カードは複数選択（チェック）、内側は単一選択（ラジオ）だが見た目が近い | 内側はセグメント型コントロール（`.mode-switch` 系）にして区別 |
| 予告表示のコントラスト | 未選択時のグレー文字は AA を満たさない | 予告は「選ぶと縦横比・解像度を指定できます」の 1 行要約に置き換え、選択肢自体は展開後に出す |
| 古いフローが前提 | 4 ステップ・左縦ステッパーは P1 以前。現行は 7 ステップ・上部横一列 | 骨格は採用しない。要素 a〜d を部品単位で移植 |
| 細部 | クレジット残「31.5 本」のような小数は「1 クレジット = CM 1 本」の約束と矛盾 | 表示を整数に（端数は内部保持、UI は切り捨て＋「残り」表現） |

## 4. カスタム形式（4:5 / 21:9 プリセット）の設計メモ

- `output.formats[]` に `{id:'portrait45', w:1080, h:1350}` と `{id:'cinema', w:2560, h:1080}` を追加できる構造は既にある（formats は配列）。
- 必要な裏側: `delivery.FORMAT_DEFAULT_PLATFORM` と配信先の上限表、`delivery.composition_id`（Remotion の構成 ID の命名）、`SpotAd` の `useAspect()` 分岐（現在 wide / vertical / square の 3 値）、`remotion_props` の `anchorX`（4:5 は vertical 寄り、21:9 は wide 寄りの切り出し）、Veo は 16:9 で生成して切り出し（9:16 は専用生成）。
- コスト: レンダー本数が増える（3 案 × 形式数）。1 形式あたりローカル 5〜15 分。先に Remotion の並列化かクラウドレンダーの目処を付けてから公開する。
- 4K: Veo 1080p ソースのアップスケールになり品質保証ができない。当面は提供しない。

## 5. 進め方

1. §2 の 1〜4 を現行フローに反映（UI のみ、1〜2 日）。
2. §4 のプリセット 2 種を設計・見積もり（パイプライン側の変更量を出してから着手判断）。
3. 自由比率・自由 px・4K は保留（要望が出たら Pro 以上の機能として再検討）。
